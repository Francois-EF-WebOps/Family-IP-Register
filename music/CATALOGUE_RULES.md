# Catalogue rules

## Canonical separation
Song = creative work. Composition = lyric, melody, arrangement, translation, or version. Recording = exact audio file/render. Release = distribution package. Identity = artist, persona, collaborator, platform account, or character. Source = evidence supporting a field or relationship.

Do not create a new song merely because a recording has a different filename, mix, or generation. Do not merge songs merely because titles match.

## Evidence and dates
Use confirmed, probable, candidate, unknown, or disputed for matching and attribution. Every inferred relationship must state its basis. A platform uploader/account is not automatically the performing artist, composer, or rights holder.

Dates must be typed: created_at, recorded_at, uploaded_at, released_at, file_added_at, or file_modified_at. Never convert a file modified timestamp into a release date.

## Preservation
- Never edit original lyric wording during recovery.
- Store each draft as a separate composition version; label composites explicitly.
- Keep fragments as fragments. Do not fill gaps.
- Separate lyrics from prompts, production briefs, artwork prompts, video scripts, and commentary.
- Keep source references. A normalized transcription is a derivative, not a replacement.
- Do not delete suspected duplicates; compare them later.

## Rights and release controls
Rights fields describe evidence and status; they do not create rights or prove ownership. Track author claims, contributors, source, tool/provider, applicable terms/licence, permission evidence, and clearance independently. Unknown is valid.

Internal production may continue while clearance is unresolved. Public release, sale, licensing, and distribution remain on hold until the applicable rights review is complete.

## Embedded audio tags
Canonical metadata is authoritative; embedded tags are synchronized derivatives.
Suggested fields: title, artist, album, album_artist, genre, date/year, track_number, disc_number, catalogue ID in comment, approved artwork, and exact approved lyrics.
Keep unknown tags blank. Preserve the original file and write tags to a copy.

## File facts
Record original filename/location, format, duration, sample rate, bitrate, channels, file size, observed file timestamps, and SHA-256 when available. Distinguish observed facts from computed facts. File timestamps are not creation/release dates unless proven.

## Public repository hygiene
Do not commit private recordings, personal data, credentials, private exports, or copyrighted source files without a clear reason and permission. The repository is public; every committed record is public.
